**Date:** 2026-11-06

**Objective:** build and validate the operational harness for the later

**Research verdict:** `UNKNOWN`. This task adds execution controls and DEV

## Boundary and implementation

Base revision was `59e3876c4e81c3041453b55d8ebb3918868f4723` on
`zk-harness`. `bindcheck_zk/` was treated as an immutable JSON interface and
was not changed. No analyzer or baseline read an EVAL or recall checkout. The
only EVAL operation was a GitHub commit-object metadata read for the frozen
278-family sample; it performed no clone, source checkout, analyzer, baseline,
RPC, transaction, proof submission, address trace, contact, or disclosure.

The harness adds:

- `eval/run_heldout.py`: exact v2 family selection, annotated dataset/freeze
  gates, selection persistence before analysis, shallow SHA acquisition,
  fixed-budget BindCheck/baseline execution, at-most-once markers, restart,
  per-family results, and clone deletion;
- `eval/run_recall.py`: the same gates and at-most-once policy for all 16
  strict resolved vulnerable/fixed pairs, with predicate, build, location, and
  E4 outcomes kept separate;
- `eval/summarize.py`: four-verdict per-stratum/overall counts, arbitrary
  UNKNOWN reasons, deterministic family bootstrap intervals, and baseline
  comparison;
- `eval/adjudicate.py`, `adjudication-template.csv`, and `ADJUDICATION.md`:
  confidence-blind separate rating sheets and validated Cohen's kappa; and
- `eval/README.md`: label/tag prerequisites, exact real-run commands,
  restart rules, and observed/planned resource envelopes.

`eval/recall-expectations.csv` intentionally leaves all 16 expectations
`UNREVIEWED`. The EVAL recall runner refuses until an independent author maps
every case to one P1–P5 predicate and vulnerable source-location regex and the
reviewed file hash is included in the freeze tag. This prevents analyzer output
from becoming its own recall oracle.

## Gates and selection

EVAL analysis requires all of the following at once:

1. `BINDCHECK_EVAL_AUTHORIZED=1`;
2. an annotated `bindcheck-zk-frozen-*` tag at `HEAD` whose recorded analyzer
   and source-ledger hashes equal the live `freeze.sh` result and ledger;
3. an annotated `bindcheck-zk-dataset-v2-*` tag whose annotation and stored
   ledger bytes equal the current source ledger (and recall ledger for recall);
4. the current source ledger hash; and
5. for recall, matching recall-ledger and reviewed-expectations hashes.

Unit tests separately confirmed refusal for missing environment authorization,
missing freeze tag, mismatched freeze metadata, missing dataset tag, and
post-tag dataset mutation. Lightweight and stale tags fail closed.

The selector independently reproduces exactly 278 EVAL-only families: 38
`verified-deployed` and 60 each from `deployed-address-in-docs`,
`audited-production`, `hackathon-student`, and `unclassified`. Every family
hash is `SHA256("bindcheck-eval-v2-family-sample-2026-11-03|" +
v2_family_id)`; no selected family overlaps DEV. The JSON/CSV selection stores
the source-ledger hash, family sample hash, canonical-row hash, repository,
commit, and recorded paths before any tool-attempt marker can be created.

## Assumptions, limitations, and next task

- GitHub commit API existence does not establish buildability, source/circuit
  correspondence, or continued future availability.
- The five DEV families estimate operations, not held-out runtime or accuracy.
- Baseline tool absence/failure is coverage `UNKNOWN`, never comparative
  superiority.
- Bootstrap intervals describe the eventual sampled families and their
  observed four-verdict records; they do not repair unsupported coverage or
  justify an ecosystem-prevalence denominator.
- The recall expectation sheet remains deliberately unfinished, and neither
  dataset nor operational tag was created in this task.

Recommended next task: independent human review and freeze. Completion means
all required EVAL labels and 16 recall expectations are signed, every
pre-analysis correction is committed with refreshed hashes/sample if needed,
both annotated local tags pass `--preflight`, and the analyzer content hash is
still `d8510859...`. Only then run the exact one-shot EVAL command; every
scheduled family must end in a schema-valid result or explicit `UNKNOWN`, with
no rule, hint, budget, or retry change after outputs are observed.

## 1. Objective and outcome

D1P-40 correctly failed closed on Payy's 1,005-to-1,003 recursive-public-input
boundary and dynamic message-memory dependencies. D1P-41 then showed that the
existing full rule set detected no additional example beyond an unjoined union
of producer and consumer facts. This task implements the missing development
capability: compare the condition under which each producer public word is
proof-enforced with the condition under which the consumer relies on that word.

The bounded outcome is:

1. a Payy mapping certificate connects 1,005 inner public words to two exact
   recursive-verifier configuration constants plus 1,003 Solidity-visible
   words; it replays 1,630 polynomial identities and fails closed on artifact,
   path, position, totality, or identity-certificate disagreement;
2. producer facts now record `EXACT` `always`, `never`, or prefix conditions,
   and preserve `UNKNOWN` for unresolved dynamic memory;
3. compiler-AST consumer facts record the reliance condition of every verifier
   word, including `word_offset < messages_length` for all 1,000 Payy messages;
4. new rule `R-EXTENT` warns when consumer reliance is not covered by producer
   binding and emits both conditions and the uncovered region; and
5. WT-C02's alleged `max_fee` undercount is **not a bug**. The pinned artifact
   contains three proof-enforced occurrences and three separately inventoried
   Brillig occurrences. WT-C02 removes the integer comparison and has zero of
   each.

Payy earlier now emits:

```text
producer: word_offset < active_messages_count
consumer: word_offset < messages_length
uncovered: active_messages_count <= word_offset < messages_length
```

Payy check-added emits no `R-EXTENT`: its complementary tail-zero constraints
make all message words proof-enforced. This silence is not a security verdict.
Both are exposed development cases. The implementation is deliberately marked
`v1.4-dev`; this task performs no freeze, held-out scan, new proof, live-chain
action, disclosure, compiler-version work, or opcode-coverage work.

## 5. Exact Payy 1,005-to-1,003 certificate

### 5.1 What is certified

The certificate is not a width-difference or selector-prefix inference. It
decodes the actual inner `agg_agg` artifact and the actual `agg_final` bridge,
certifies the recursive verifier call, and independently replays every stored
polynomial identity against the serialized bridge ACIR.

For Payy earlier:

- inner artifact SHA-256:
  `83b75a4af7434c9c722f19f7638404bd45ddbbd2ec0ff85b779bf89ca31d3b2c`;
- bridge artifact SHA-256:
  `92f05bfe7190de8ae2f5bdc895277c304c6d51afffae411e4f27148c51ffe0`;
- inner words: 1,005;
- exact configuration constants: producer indices 0 and 1,
  `verification_key_hash[0]` and `verification_key_hash[1]`;
- mapped words: 1,003, from consumer index 0 / producer index 2 / `old_root`
  through consumer index 1,002 / producer index 1,004 / `messages[999]`;
- replayed polynomial identities: 1,630; and
- certificate SHA-256:
  `80f1e490dfbf1baebf0ba4bac6bebaefc5a4d0d277565c586c82bd737709b555`.

Check-added independently produces the same cardinalities and identity count;
its certificate SHA-256 is
`3e5b095016960e91a68d0e73fc9c430ed413aff18da8797abf3511073e7eb456`.

The Solidity frontend accepts a shorter direct verifier array only when this
certificate is supplied and validates its artifact counts, total index set,
and every producer path. The analyzer re-verifies the embedded certificate
against both artifacts. Missing, stale, partial, duplicated, reordered, or
tampered facts fail closed. Benchmark Payy mutants remain unsupported because
this task does not infer or manufacture bridge certificates for mutated
artifacts.

### 5.2 Limits

The certificate proves the decoded recursive-call argument equalities for the
named local artifact bytes. Recursive proof-system soundness, correct compiler
decoding, deployed bridge selection, and matching deployed verification keys
remain explicit external assumptions. It is not a deployment certificate.

## 6. Conditional producer and consumer facts

### 6.1 Producer

The producer frontend emits one fact per public ABI leaf with `status`,
normalized `condition`, and evidence. It recognizes two bounded Noir forms:

- literal loop-index guards such as `if i < active_count`; and
- a monotonically incremented dynamic index whose array is matched to exactly
  one decoded `MemoryInit` block and read-only `MemoryOp` set.

Payy earlier's 1,000 message leaves all receive the exact prefix condition
`word_offset < active_messages_count`. The matched local evidence is source
SHA-256 `c44a67e6...`, source line 25, memory block 2, 1,999 dynamic reads, and
zero writes. Check-added has the same memory shape plus the complementary
tail-zero assertion, so every message leaf receives `always`; its source
SHA-256 begins `3fd7c851...`.

An unresolved or near-miss dynamic-memory form receives `UNKNOWN`; it never
becomes covered or safety evidence. Existing analyzer execution still fails
closed before rules when such producer facts are required.

This is deliberately a bounded source/ACIR-correspondence extractor, not a
general symbolic Noir path engine. The recognized source hash, exact ABI
witness set, unique memory block, read/write inventory, and condition evidence
are emitted so the conclusion can be audited.

### 6.2 Consumer

The Solidity compiler-AST frontend propagates affine loop indices and storage
or parameter extents. It records reliance where a verifier word reaches a
guard, storage write, or modeled effect. Literal extents become
`configured_length`; symbolic extents are normalized to lower snake case.

For Payy, producer indices 5 through 1,004 (`messages[0..999]`) all receive
`word_offset < messages_length`. The condition includes the exact verifier
array offset relation (`array_offset=3`, `limit_offset=3`), so the header does
not shift the message-relative word offset. The extracted warning location is
`consumer_source.sol:522`.

The frontend preserves loop-condition dependence rather than widening a
symbolic loop to an unconditional union. Unsupported/disjunctive forms remain
`UNKNOWN` unless represented by the facts interface.

## 7. R-EXTENT

`R-EXTENT` asks whether consumer reliance implies producer binding. It reports
`covered=true/false` only for exact supported condition pairs. `UNKNOWN` never
suppresses an existing rule and never becomes a no-warning assurance.

The bounded comparator handles `always`, `never`, equal normalized prefixes,
and unequal prefixes. Adjacent array leaves with identical facts are grouped
into one diagnostic. The Payy earlier warning contains all 1,000 message paths,
both conditions, and the uncovered region. Check-added produces no extent
warning because producer `always` covers consumer prefix reliance.

Classification: this resolves a **confirmed missing relational capability**
from D1P-41, not a prior false safety verdict. D1P-40's earlier `UNKNOWN` was
correct fail-closed behavior. The new Payy result is a development static
warning, not an independent `VIOLATION` verdict.

## 8. WT-C02 `max_fee` reconciliation

Classification: **not a bug**.

In the pinned beta.22 withdraw artifact, `max_fee` witness 8 appears in three
proof-enforced `AssertZero` opcodes (indices 1, 30, and 53) and three separately
inventoried Brillig call sites (indices 5, 23, and 45). WT-C02 removes
`assert(!amount.lt(max_fee))`; the mutant has zero proof-enforced and zero
Brillig occurrences for `max_fee`.

The observation that the pinned circuit accepts `max_fee=0` does not show an
undercount: zero satisfies `max_fee <= amount`. The discriminating positive
control is `max_fee > amount`; the bound synthetic circuit rejects 11 over 10,
while the comparison-removed circuit accepts the same values. Therefore the
existing WT-C02 `R-BIND` identity remains correct and no counting repair is
made.

## 13. Assumptions, limitations, and verdict discipline

- All cases are synthetic or exposed development cases. No held-out evidence
  is added.
- The exact mapping is artifact-specific and assumes correct deployment/key
  selection and recursive proof soundness.
- Producer path analysis recognizes two bounded source idioms with decoded
  ACIR memory-shape checks; it is not a general path-sensitive interpreter.
- Consumer reliance covers the supported compiler-AST forms and modeled
  effects only. Unsupported forms remain `UNKNOWN`.
- Condition comparison is intentionally small. Algebra beyond exact supported
  prefixes remains `UNKNOWN`.
- A no-warning result, including Payy check-added, is not
  `VERIFIED_WITHIN_SCOPE` without the research contract's independent
  end-to-end evidence.
- AI output is not independent annotation. The emitted sources, artifacts,
  identities, controls, and warning facts require author inspection.

Accordingly, D1P-42 establishes a bounded development implementation and an E1
static diagnostic. It does not establish a new vulnerability, general
capability, security, or the D1 verdict. D1 remains **UNKNOWN**.

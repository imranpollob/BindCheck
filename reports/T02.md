## 4. Consumer
`submit(pA, pB, pC, pubSignals[10])`: (1) reverts `OldCommitmentMismatch` unless `pubSignals[8] == currentCommitment`; (2) reverts `InvalidProof` unless `verifier.verifyProof(pA,pB,pC,pubSignals)` returns true, passing all 10 signals in the T01 order (`amount[0..3]`, `active[0..3]`, `oldCommitment`, `newCommitment`); (3) only then stores `pubSignals[9]`. Constructor takes the initial commitment (T01 `oldCommitment`). `setUp` runs before each test, so every test deploys fresh verifier and consumer; it also asserts the loaded fixture equals the T01 example values.

## 6. Unexpected finding / limitations
- **Gas:** the off-curve test used ~1.07 billion gas (the other tests ~0.52–0.57M). The generated verifier forwards `gas() - 2000` to the pairing precompile; a malformed point makes the precompile fail and burn all forwarded gas, and the verifier then returns `false` instead of reverting. Forge's test gas limit hides this; on a real chain the call would consume the transaction's gas limit. Recorded, not addressed.
- Forge lints generated-verifier constant naming (notes only, no failure).
- Not run: fresh-machine rehearsal, other EVM versions/chains, fuzz/invariant tests, replay of the same proof after acceptance, Hardhat. Parsing of `calldata.json` is test-local; the verifier argument order was checked only by the honest proof verifying, with `pB` as emitted by `soliditycalldata`.
- Proof bytes are randomized per T01 run; each `t02.sh` run exports the verifier from the current T01 zkey, so verifier and fixture stay matched.

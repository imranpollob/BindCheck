## 3. Versioned beta.22 decoder

The new reader is
`src/bindcheck_d1/frontends/acir_binary_beta22.py`. It is independent from
`acir_binary_v1.py`, whose beta.14 legacy-bincode version gate and behavior are
unchanged. The beta.22 artifact decompresses to 8,896,657 bytes and begins
with format byte `3`, Noir's MessagePack-compact encoding at this release.
Decoder schema provenance is hash-recorded from the exact compiler source in
`results/raw/D1P-13/decoder-inventory.json`.

The reader enforces compressed/decoded byte, collection, and depth limits;
canonical field encodings; exact compiler and format versions; canonical
witness sets; structural enum shapes; and trailing-byte rejection. An unknown
opcode, black box, Brillig form/opcode, memory block type, or serialization
form raises a named `Unsupported` reason. It never skips an unknown item.

Parsing is deliberately distinct from semantic checking. In this artifact the
decoder parses:

| ACIR kind | Count | Semantic status |
| --- | ---: | --- |
| `AssertZero` | 24,860 | supported proof-enforced constraint |
| `RANGE` | 107 | supported proof-enforced constraint |
| `Poseidon2Permutation` | 86 | parsed; proof-enforced semantics unsupported |
| `BrilligCall` | 20 | parsed; witness generation, not a proof constraint |
| `MemoryInit`, `MemoryOp`, constrained `Call` | 0 each | parsed, checker would report unsupported if present |

Five unconstrained functions contain 96 Brillig VM instructions: 10
`BinaryFieldOp`, four `BinaryIntOp`, four `Call`, five `CalldataCopy`, three
`Cast`, 33 `Const`, three `Jump`, three `JumpIf`, 21 `Mov`, four `Return`, five
`Stop`, and one `Store`. They are inventoried rather than interpreted as
constraints.

The focused beta.22 tests and existing beta.14 regression files pass together:
58 tests and 284 subtests, with no failures. The complete D1 suite also passes
197 tests and 312 subtests. Controls cover truncation,
trailing bytes, named unknown-opcode/black-box rejection, parse/semantic
separation, including named fail-closed rejection for an unsupported Brillig
black box, arithmetic evaluation, range evaluation, and the existing typed
reader behavior.

## 4. Honest witness and semantic checking

`scripts/fixtures/d1p_13_extract_witness.ts` loads the rebuilt artifact and
the exact saved `proofInputs` from `results/raw/D1P-12R/honest-proof.json`,
then calls `Noir.execute`. It never imports or calls a proving backend. The
resulting main witness map contains 25,384 values. Its witnesses 0–10 exactly
equal the accepted proof's saved public inputs. The execution record marks
zero prover calls; no D1P-12R proof-attempt slot was consumed.

`acir_semantics_beta22.py` evaluates arithmetic expressions modulo the BN254
scalar-field modulus and enforces `RANGE` as `value < 2^num_bits`. On the honest
witness:

| Semantic class | Supported | Satisfied | Unsupported |
| --- | ---: | ---: | ---: |
| arithmetic `AssertZero` | 24,860 | 24,860 | 0 |
| `RANGE` | 107 | 107 | 0 |
| Poseidon2 permutation | 0 | not claimed | 86 |
| **proof-enforced total** | **24,967** | **24,967** | **86** |

All 25,073 constrained-function opcodes are classified: 24,967 supported
constraints, 86 unsupported proof constraints, and 20 witness-generation
calls. `no_skipped_opcodes` is true. The unsupported Poseidon count prevents a
whole-circuit satisfaction conclusion even though the supported component is
fully satisfied.

### Mutation controls

`mutation-plan.json` was written and hash-frozen before either mutation was
evaluated. Both selections had a decoded supported target constraint and a
precomputed expected failure:

| Mutation | Predeclared target and reason | Observed |
| --- | --- | --- |
| witness 2 (`amount`) `5e18 → 5e18+1` | opcode 1 polynomial becomes `P−1`, not zero | target `AssertZero` failed with residual `P−1`; three arithmetic failures total |
| witness 12 `0 → 2` | opcode 0 requires a one-bit value, so `2` violates `< 2^1` | target `RANGE` failed; one range and 76 arithmetic failures total |

The extra observed failures are reported rather than treated as errors: one
witness can participate in several constraints. Both named expectations match.
No mutation was selected merely because it was an intermediate, inactive, or
unconstrained value.

## 3. The repair (`results/raw/T05/repair.diff`, mutant → repaired)
Besides header/name, one error and one check, placed **after** the verifier accepts all ten public inputs (so the flags it reads are authenticated):
```
for (uint256 row = numRealTxs; row < ROWS; row++)
    if (pubSignals[ACTIVE_OFFSET + row] != 0) revert ActiveRowOutsidePrefix(row);
```
`numRealTxs` stays bounded 0–4 (`InvalidNumRealTxs`), and the old-commitment check, real verifier call, funding rules, escrow checks, and consumption rules are untouched.

**Why this blocks the defect, for this circuit:** the circuit constrains each flag to Boolean, forces `amount = 0` when `flag = 0`, and sets `newBalance = oldBalance + Σ flag·amount`. A flag-0 row therefore contributes nothing to the balance update. If every row outside the prefix has authenticated flag 0, every flag-1 row lies inside the prefix, where each must have a funded, exact-amount, unconsumed entry that is consumed, so consumption covers the full credit Σ flag·amount. The T04 scenario (row 3 active, limit 3) now fails the new check. This argument depends on those specific constraints and is **not** claimed for other circuits (e.g. ones where a flag-0 row can still affect state).

## 5. Limitations
- Sufficiency is circuit-specific (§3). The rule is flag-based, so an active row with amount 0 outside the prefix is also rejected (conservative).
- `numRealTxs` remains an unauthenticated caller choice; the repair makes the outcome safe for this circuit rather than removing the parameter.
- The deposit identity `(batchId,row)` and 1 unit = 1 wei are demonstration conventions; the initial 1,000 balance is outside this incremental-backing measurement. No withdrawals or solvency claim.
- Public inputs and funding amounts are on-chain; commitments are unsalted (no confidentiality).
- Gas observation from T02 (off-curve proof point) remains open and was not investigated.
- Not run: fresh-machine rehearsal, fuzzing of flag/limit combinations, other circuits, multiple batches per consumer.

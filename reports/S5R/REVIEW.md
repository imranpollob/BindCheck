## Answers to the six review questions

1. **Spent-family contamination — CLI protected; helper path is not pair-bound.** `eval/reserve.py:38-65` checks the pinned manifest hash, 1,105 distinct IDs and pairs, the spent pair set, and WarpToad before `main` runs (`eval/reserve.py:212-230`). An offline comparison found 1,105 unique manifest pairs, zero overlap with the 278 spent pairs, and no WarpToad row. `ReservePermit.allows` limits repositories to manifest names (`eval/reserve.py:114-120`), but `run_unit` authorizes only the repository and passes the supplied commit to acquisition (`eval/reserve.py:170-179`). A direct helper call with a manifest repository and an unlisted commit can therefore acquire a non-manifest unit after the gate is valid. See S5R-01. The current spent set shares no repository name with the manifest, so that path does not reach a currently spent pair.
2. **Guard bypass — ordinary CLI refusal remains; permit is conditional.** `scripts/check_holdout.py:65-78` is unchanged by S5H, and `reserve_decision` checks the caller path and a `ReservePermit` (`scripts/check_holdout.py:51-62`). The permit rechecks the manifest hash and full gate (`eval/reserve.py:114-125`); a non-manifest repository cannot pass it. The gate requires `s5-reserve-run` to peel to HEAD, analyzer equality to `freeze-3`, the content digest, and a present record with matching manifest hash and nonblank approval fields (`eval/reserve.py:75-105`). The record is a local assertion of approval, not a cryptographic author signature. No authorization file or run tag is present in this checkout, so the present gate cannot pass. The pair-level helper gap is S5R-01.
3. **Frozen analyzer — checked for the declared files and digest.** `eval/reserve.py:81-90` compares committed `bindcheck_zk/` and `freeze.sh` bytes to `freeze-3` and runs the live content-hash calculation. That digest covers the analyzer launcher, top-level Python modules, requirements, config, and vendor lock (`bindcheck_zk/freeze.py:7-17`). A changed covered analyzer file fails one of these checks. The gate does not freeze the harness or its evaluation helpers; a resumed run can mix harness versions under the same gate (S5R-03).
4. **Silent drops — normal results get one status, but classification and evidence are incomplete.** New `run_units` results require a funnel status and every manifest ID must appear once (`eval/reserve.py:135-166`); runner exceptions become `HARNESS_ERROR` (`eval/reserve.py:146-157`). Yet an analyzer process failure or non-JSON result becomes `UNSUPPORTED` (`eval/reserve.py:191-199`, `eval/run_heldout.py:339-350`), contradicting the promised separation (S5R-02). A resumed `result.json` is accepted without validating its status or evidence (`eval/reserve.py:140-145`), and warning source bytes are not retained before checkout deletion (`eval/reserve.py:187-204`; S5R-04). A successful prebuild of one circuit also hides failure of another in the unit-level `BUILT` status (`eval/prebuild_heldout.py:74-84`).
5. **One-shot integrity — gate/tool path equality is checked; output and harness identity are not sealed.** `eval/reserve.py:220-230` refuses a different recorded gate or Circom path/digest on resume. It does not record or check hashes of the harness and helpers; it accepts existing per-unit results based only on repository and commit, and writes `funnel.json` again (`eval/reserve.py:140-166`). A changed harness or replaced result file can be folded into a resumed funnel under the same gate (S5R-03). The output tree is an ordinary writable directory, with no external one-shot ledger or append-only seal.
6. **Historical freeze-2 path — unchanged in the reviewed diff.** `eval/common.py` (`select_families`, `check_eval_gate`) and `eval/run_heldout.py` have no diff against `origin/main`. `eval/prebuild_heldout.py:46-84` extracts the same build loop into `prebuild_checkout`; its ordinary `prebuild_family` still calls that loop, and the new `--sample` option accepts only the historical sample (`eval/prebuild_heldout.py:126-143`). The guard CLI's `main` is unchanged (`scripts/check_holdout.py:65-78`). This is a source and offline regression conclusion, not a full rerun of freeze-2.

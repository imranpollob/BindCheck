# T22 — ACIR/SMT message-tail evaluation

**Status:** IN PROGRESS. No T22 verdict is claimed by this report yet.
**Research scope:** owned local defensive analysis; no live transactions or third-party systems.
**Authority:** [`docs/research-contract.md`](../docs/research-contract.md).

## 1. Objective

Evaluate whether a small declarative message-layout specification plus generic finite-field reasoning over compiled ACIR can distinguish an unconstrained public-message tail from legitimate tail-zero implementations without depending on the Noir source idiom recognized by T21.

T22 is not yet a general proof-to-execution checker. It tests one producer-side property needed by the Payy case:

> Every public message word after the prefix derived from verified inner-proof outputs is zero.

The Payy cases are in-sample. They test semantic behavior and contrast with T21, but cannot establish generalization.

### T22-v2 feasibility gate — 20 October 2026

**Gate status: PASSED. T22 remains IN PROGRESS; the nine-case evaluation was not run.**

T22-v2 specializes only the empty-prefix refutation probe. When every declared stream has an activation predicate, the query fixes those predicates to zero, performs bounded exact polynomial propagation, lowers fixed-index memory reads, and prunes existentially solvable equalities. Definitions that exceed the propagation cap remain for the solver. This changes query scheduling and simplification, not the message-tail property or specification.

The single frozen earlier `agg_agg` case was run with the pinned Payy revision `c4d2c9021b8fb9988816eb6987a734b830bfce15`, Noir `1.0.0-beta.14` (`60ccd48e18ad8ce50d5ecda9baf813b712145051`), and the CoCoA-enabled cvc5 `1.4.2` build (`282d5e0c84baf49c780704c532f87ba66d8b513d`):

```bash
T22_ONLY_CASE='A agg_agg (earlier)' \
NARGO="$PWD/tools/noir-1.0.0-beta.14/nargo" \
CVC5="$PWD/tools/cvc5-1.4.2-gpl/bin/cvc5" \
T22_BACKEND=cvc5 TLIMIT=300 \
python3 -I scripts/t22_eval.py build/T22/scratch \
  results/raw/T22/30_v2_gate/20_gate.json
```

Observed result:

| Measure | T22-v1 | T22-v2 gate |
|---|---:|---:|
| Selected opcodes | 587 | 0 |
| Selected witnesses | 523 | 1 |
| Implied constants | — | 487 |
| cvc5 result | timeout at 960 s | `sat` at reported 0.0 s |
| T22 wall time | >960 s | 4.1 s |

The saved SMT query asserts only `w1275 != 0`; cvc5 returns `sat` with `w1275 = 1`. Together with the specialized premises `proofs[0].old_root = proofs[1].old_root = 0`, this is the bounded empty-prefix counterexample. No unmodeled black-box output remains in the selected component. Components outside the cone are still assumed satisfiable, exactly as in the frozen T22 design; the result does not independently establish recursive-proof feasibility or an end-to-end exploit.

The implementation's raw label remains the pre-contract spelling `VIOLATED`; under the authoritative research contract this gate is recorded as a bounded **VIOLATION**. Verdict-label normalization is required before the full evaluation.

## 4. Independent transfer case

The frozen secondary candidate is Aztec's `mock-protocol-circuits` at commit `c4ecc607f3ea8e3977259830ba982797c1e39ce7`, using `mock-private-kernel-inner` and `mock-private-kernel-init`. The manual expectation recorded before running T22 is `SATISFIED_AT_SCOPE` for both.

## 5. Planned secondary experiments

These experiments are exploratory unless separately frozen before execution:

- specification sensitivity: remove or alter one semantic mapping at a time;
- specification size and authoring/correction effort;
- comparison with T21 on equivalent but syntactically different tail checks;
- full-size feasibility probe, reported separately from the bounded result; and
- failure classification for unsupported opcodes, timeouts, and unmodeled black boxes.

## 6. Completion criteria

T22 is complete only when this report contains:

1. exact tool versions, host, revisions, commands, and run hashes;
2. all primary outcomes, counterexamples, non-vacuity results, runtime, and mismatches;
3. an explanation of every `UNKNOWN`;
4. a preserved independent-case run or an exact blocker;
5. specification burden and sensitivity results;
6. comparison with T21 under the same cases; and
7. limitations distinguishing bounded producer analysis from proof-to-execution generalization.

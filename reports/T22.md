# T22 — ACIR/SMT message-tail evaluation

**Status:** IN PROGRESS. The T22-v2 primary sweep is complete, but it failed the
frozen expectations (2/9 matches, 6 `UNKNOWN`, and one negative-control
`VIOLATION`). Section 3.2 diagnoses all three failure classes. In particular,
the negative-control `VIOLATION` is a confirmed analyzer false positive caused
by unsound probe specialization. No overall T22 verdict or security finding is
claimed.
**Research scope:** owned local defensive analysis; no live transactions or third-party systems.
**Authority:** [`docs/research-contract.md`](../docs/research-contract.md).

## 1. Objective

Evaluate whether a small declarative message-layout specification plus generic finite-field reasoning over compiled ACIR can distinguish an unconstrained public-message tail from legitimate tail-zero implementations without depending on the Noir source idiom recognized by T21.

T22 is not yet a general proof-to-execution checker. It tests one producer-side property needed by the Payy case:

> Every public message word after the prefix derived from verified inner-proof outputs is zero.

The Payy cases are in-sample. They test semantic behavior and contrast with T21, but cannot establish generalization.

### T22-v2 feasibility gate — 20 October 2026

**Gate status: PASSED.** At this checkpoint T22 remained in progress and the
nine-case evaluation had not been run; Section 3.1 records the later sweep.

T22-v2 specializes only the empty-prefix refutation probe. When every declared stream has an activation predicate, the query fixes those predicates to zero, performs bounded exact polynomial propagation, lowers fixed-index memory reads, and prunes existentially solvable equalities. Definitions that exceed the propagation cap remain for the solver. This changes query scheduling and simplification, not the message-tail property or specification.

### 3.2 T22-v2 failure diagnosis — 20 October 2026

**Status:** diagnosis complete for all three failure classes. No verdict in
Section 3.1 is changed and no repair was implemented or run. The frozen
analyzer (`scripts/t22_tailspec.py`, SHA-256 `d45ccef0…`, unchanged) was only
imported. `results/raw/T22/31_v2_primary/` was not modified; its manifest,
JSON and log hashes still match Section 3.1.

#### Method

1. **Same artifacts.** The nine preserved work trees were copied from
   `build/T22/scratch-31_v2_primary/` to `build/T22/scratch-32_v2_diagnosis/`
   and recompiled with the pinned `nargo 1.0.0-beta.14 --print-acir`. All nine
   compiles exited 0, and every regenerated bytecode and ABI is byte-identical
   to the targets the primary run analyzed. Two pairs compile to identical
   ACIR text: earlier `agg_agg` = `m3`, and `agg_utxo` = `m6`.
2. **Reproduction.** `scripts/t22_diag.py` re-ran the v2 empty-prefix
   specialization for every slot of every case. It reproduced every primary
   probe size (0/1, 32/24, 24/18, 28/21, 0/1, 0/1) and the `agg_utxo` abort
   at slot 0.
3. **Provenance.** It re-ran constant discovery with provenance tracking. On
   every non-contradiction slot, the traced constant map equals the frozen
   `_discover_constants` result.
4. **Certificates.** For every forced message witness and every
   contradiction, it solved a *subset certificate* with cvc5 (default `gb`
   mode, 120 s): only the original, unspecialized ACIR assertions in that
   provenance, plus the probe premises. An UNSAT subset implies that the full
   ACIR relation is UNSAT under the same premises. SAT controls with one
   premise removed check that the subset is not trivially inconsistent.
5. **Solver mode.** Timed-out preserved queries were copied (hash-identical)
   and re-solved under cvc5's alternate finite-field mode
   `--ff-solver=split`. This is a diagnostic only; the frozen protocol uses
   the default `gb` mode.

#### Class 1 — running-flag `VIOLATION` is an unsound specialization, not an ACIR model (confirmed)

Mechanism, read from the ACIR and the frozen source:

- **Witness map.** `w1275..w1282` are `messages[0..7]`; `proofs` occupies
  `w0..w1269`.
- **Compiled flag loop.** It becomes is-zero gadgets on
  `messages_index - i`: `w2303 = -(w1771*w1781 + w1776*w1780)`,
  `w2305 = 1 - w2303*w2304`, `0 = w2303*w2305`. These feed an OR chain
  `past_k = past_{k-1} + eq_k - past_{k-1}*eq_k`. Each tail check is
  `0 = messages[k]*past_k`; for example, line 1209 is
  `ASSERT 0 = w1275*w2305`.
- **The implied constants are correct.** With both `old_root` activations
  fixed to 0, exact propagation forces `messages_index = 0`, then `past_0 = 1`,
  then every `past_k = 1`, and finally `messages[k] = 0` for **all eight**
  slots.
- **Where the constraint is lost.** `_specialize_probe_component` substitutes
  these constants into every retained assertion. `0 = w1275*w2305` becomes the
  zero polynomial and is dropped (`if not e: continue`), and every other
  occurrence of `w1275` disappears in the same way.
- **Where the goal goes wrong.** `probe_query` then builds the goal from the
  **unsubstituted** `M[k]` (`ff.expr(M[k])`) and asserts `w1275 != 0`. It never
  asserts `w1275 = implied[w1275]`. The implied equality is lost, so the
  saved query `w1275 != 0` is a strict relaxation of the ACIR relation and its
  `sat` is spurious.
- **Selection amplifies it.** `min(candidates, key=(ops, witnesses, slot))`
  always prefers a slot whose constraints were all erased (0 ops, 1 witness).

Artifact-backed results:

| Check | Result |
|---|---|
| Message witnesses forced to 0 under the premise | 8/8 slots (`w1275..w1282`) |
| Subset certificate, premise + `messages[k] != 0`, from original ACIR assertions | **UNSAT for all 8 slots** (363–391 assertions, 8.2–10.1 s each) |
| Control: same subset + premise, without `messages[0] != 0` | SAT (29.5 s) |
| Control: same subset + `messages[0] != 0`, without premise | undecided: `unknown` under `gb` (120 s) and killed under `split` (300 s) |

**Conclusion (model-confirmed):** no ACIR model satisfies the reported
running-flag counterexample. The `31_v2_primary` running-flag `VIOLATION`
is an analyzer false positive caused by unsound specialization. It is not a
Payy finding.

**Latent instance.** In `m1`, slot 1 is compiled as an is-zero gadget
(`1 > messages_index` becomes `messages_index == 0`). That slot is also forced
to 0 (certificate UNSAT, 363 assertions), and the frozen reduction for it
leaves the target in none of its 24 retained ops. Had slot 1 been selected,
`m1` would have produced a second spurious SAT.

**True positives unaffected.** The earlier `agg_agg` case and `m3` have no
forced message witness on any slot. Their 0-op probes therefore do not depend
on this defect.

#### Class 2 — timeout `UNKNOWN` (check-added `agg_agg`, `m1`, `m2`): three confirmed mechanisms and one open limit

Each case spent 60 s on the probe and then 3 × 300 s on the general queries.

1. **Probe solver mode (confirmed).**
   - The preserved probes for B, `m1` and `m2` encode 264, 198 and 231
     range-bit variables. They timed out under `gb`.
   - Hash-identical copies are UNSAT under `split` in 0.55, 0.34 and 0.45 s.
   - Each case's single-slot target query (3 ACIR witnesses, 33 bits) also
     times out under `gb` at 60 s, and is UNSAT under `split` in 0.02–0.03 s.
   - The bottleneck is `gb` on the 32-bit remainder from the compiled
     comparison gadget `2^32 + i - messages_index = 2^32*q + r`.
2. **No re-componentization after substitution (confirmed).** Once
   `messages_index` is constant, the eight per-slot gadgets share no witness.
   `_specialize_probe_component` nevertheless keeps every op of the
   pre-substitution component. For B, that is 8 × 4 ops and 8 × 33 bits
   (32 ops, 264 bits), against 4 ops and 33 bits for the target slot alone.
3. **The probe tests the wrong slot in both violating mutants (confirmed).**
   - `m1`: slot 0 has no tail check, because the compiler drops
     `0 > messages_index` for `u32`. Its reduced query (24 ops/19 witnesses)
     never mentions the target. Slot 2 (24/18), a constrained slot, wins the
     tie-break by one witness.
   - `m2`: unchecked slot 7 (28/22, target absent) loses to constrained
     slot 0 (28/21).
   - Even a decided probe would have been UNSAT in both mutants, so it could
     not yield their expected `VIOLATION`.
4. **General-query scalability (open; hypothesis only).**
   - The general cones contain 544–546 assertions, 15 memory reads, 48–50
     32-bit range checks plus 6–8 1-bit range checks, 1,542–1,608 encoded bit
     variables, and 219 `ite` terms from the walk derivation.
   - Under `split`, all three preserved `nonvacuous` queries were still
     killed at 300 s (exit 137).
   - Bit decomposition is the leading hypothesis, but it was not isolated.
   - This is the binding limit for the check-added case, which can only reach
     `VERIFIED_WITHIN_SCOPE` through the general queries.

None of these cases is called safe or violating; all three remain `UNKNOWN`.

#### Class 3 — `agg_utxo` contradiction is a genuine infeasible premise handled as unsupported (confirmed)

The probe's empty-prefix premise (every stream inactive) sets
`proofs[0..2].utxo_kind` (`w623`, `w1776`, `w2929`) to 0. In all three `agg_utxo` variants, constant discovery stops at
ACIR line 28, `ASSERT 0 = w623*w3607 - 1`. That is the compiled form of
`assert(!is_padding, "first proof cannot be a padding proof")`, because
`utxo_kind` must have an inverse.

The one-assertion certificate behaves the same in all three variants:

| Premise | Result |
|---|---|
| All activations zero | UNSAT |
| No premise | SAT |
| Only `w623` zero | UNSAT |
| Only `w1776` zero | SAT |
| Only `w2929` zero | SAT |

**Root cause:** the contradiction is genuine, but narrow. What is established
is that the probe's specific premise is infeasible: every stream inactive, and
in fact `proofs[0].utxo_kind = 0` alone. This does **not** show that an empty
prefix (`L = 0`) is impossible in `agg_utxo`.

Under the specification, stream 0 can be active with a first word other than
2 or 3. In that case the walk emits nothing and `L = 0`. The source has no
assertion that restricts `utxo_kind` to {0, 2, 3}. Whether such an `L = 0`
assignment satisfies the ACIR was not checked.

The `UNKNOWN` comes from control flow, not from a missing model:

- `_discover_constants` raises `Unsupported`;
- `run()` returns before issuing any `nonvacuous`, `prefix` or `tail` query;
  and
- the probe had refuted only its own premise. That shows no counterexample
  exists with every stream inactive. It does not exclude `L = 0`
  counterexamples with an active stream, which only the general `tail` query
  covers. A refuted premise is different from an unsupported case.

**Not established:** whether the general queries over these approximately
34,600-opcode ACIR files would finish, because they were never issued.

**Latent hazard:** `scripts/t22_diag_blackbox.py` shows that in every
`agg_utxo` variant, 323 unmodeled `POSEIDON2_PERMUTATION` outputs in the probe
component are removed by `prune_dangling`. That function treats them as
solvable witnesses, so they never reach the probe's `free` (unmodeled-output)
warning. Any future SAT on these cones could therefore be spurious without a
warning. No `agg_agg` selected component contains an unmodeled black-box
output, even before pruning.

#### Proposed T22-v3 repair (designed only; not implemented or run)

No change below alters the message-tail property, the specifications, the nine
cases or their frozen expectations. Any repair must be frozen as a new
versioned encoding, run under a new run ID, and reported alongside — never in
place of — `31_v2_primary`.

| ID | Change | Soundness condition |
|---|---|---|
| R1 | Rewrite the probe goal `M[k]` with the same implied constants (equivalently, assert `w = c` for every goal witness in `implied`). A goal that reduces to constant 0 makes that slot UNSAT. | The constants are implied equalities of the original component under the premise, so this is exact. It fixes Class 1. |
| R2 | Recompute connected components after substitution and solve only the target's component. | UNSAT on a subset is sound. SAT extends the existing "components outside the cone are satisfiable" assumption to components split off by substitution, so it must be stated as such or discharged by solving the remainder. |
| R3 | Report a contradiction derived under the all-streams-inactive premise as "probe UNSAT: no counterexample with every stream inactive" and continue to the general queries instead of raising `Unsupported`. | The contradiction follows from exact substitution of implied equalities; Class 3 has one-assertion certificates. It excludes only the all-inactive assignment, not `L = 0` counterexamples with an active stream; those remain for the general `tail` query. It is never by itself `VERIFIED_WITHIN_SCOPE`. |
| R4 | Probe every slot (or one disjunction over slots) instead of only the minimum-size slot. | A scheduling change only; it removes the bias and the misses in Classes 1–2. |
| R5 | Freeze the cvc5 finite-field mode (for example `--ff-solver=split`) in the protocol and manifest before any v3 output is inspected. | A solver option, not a property change. |
| R6 | Count unmodeled black-box outputs as occurrences in `prune_dangling`. | Retaining these assertions keeps UNSAT sound, because the outputs remain free variables, and lets the existing `free` warning fire on SAT. |

R1–R4 are expected to change the running-flag control and the `m1`/`m2` probes.
They are not expected to make the general check-added queries finish
(Class 2, item 4). That case may therefore remain `UNKNOWN` under v3, which
would be reported as such.

#### Assumptions, limitations and failed approaches

- The certificates reuse T22's ACIR text parser and SMT encoder; they are not
  an independent parser. They rely on cvc5 1.4.2 finite-field soundness and on
  the `--print-acir` text faithfully describing the byte-identical bytecode.
  Z3 is not installed, so no second-solver cross-check was run.
- All results are for the bounded `N = 8` scratch instances.
- One control remained undecided: the running-flag no-premise control
  (`unknown` under `gb`, killed at 300 s under `split`). The UNSAT
  certificates do not depend on it.
- `--ff-solver=split` did not rescue the general queries.
- Solver-mode effects were measured only on preserved or diagnostic queries.
  They were not run through the analyzer and are not v2 results.

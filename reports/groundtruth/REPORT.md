These are auditor observations, made with no analyzer change. Reproducer: [scripts/check_canonical_guard.py](scripts/check_canonical_guard.py) → [canonical-guard-check.json](canonical-guard-check.json).

1. **zkDrops vulnerable revision (DEV-H01) gets P3 `VERIFIED_WITHIN_SCOPE`.** This is a revision with a locally reproduced alias replay.

   - `p4.canonical_guard` returns true. The regex `\bcheckField\s*\([^;]*(?:inputs?|pubSignals?|publicInputs?)` (`p4.py:104`) matches 19,084 characters of semicolon-free Yul (lines 183–743) and ends on an unrelated `calculatePl(pMem, pubSignals`.
   - The fixed revision (H02) also gets VERIFIED, so this gate pair would score as not detected.
2. **Semaphore alias pair (DEV-H03/H04) gets P3 `VERIFIED_WITHIN_SCOPE` with no verifier matched.** P4 on the same rows reports `VERIFIER_ARTIFACT_MISSING`.
   - Cause: in `analyzer.py:839-844`, `verifier is None` makes the FIELD_ALIAS condition false, and control falls through to `VERIFIED_WITHIN_SCOPE`.
   - So a missing artifact produces a safe-direction verdict, against research contract §8 and README ("missing artifacts … are UNKNOWN").
   - For this pair the tracked Solidity cannot tell vulnerable from fixed in any case: `semaphorejs/contracts/verifier.sol` is a symlink to an untracked build output, and the fix is a snarkjs pin.
3. **zk-email q-vs-r (row 29):** the only Solidity difference between the vulnerable and fixed revisions is the modulus inside `checkField` (`lt(v, q)` → `lt(v, r)`). The recogniser in item 1 does not check which modulus is used.

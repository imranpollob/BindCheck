## DEV corpus and native-tool outcomes

A and C each emitted candidate warnings on [26/56 rows](metrics.json), with [29/56 UNKNOWN](metrics.json) and [1/56 VERIFIED_WITHIN_SCOPE](metrics.json); these are **unconfirmed source patterns requiring human review**, not known vulnerabilities. No DEV false-alarm or detection rate is claimed because the DEV rows lack reviewed case-level labels here.

Native execution must be read separately from the arm verdict. The [invocation ledger](metrics.json) records Circom compile successes, nonzero exits, and timeouts; Circomspect exit code 1 can carry a diagnostic, as in the retained [ADV-V17 output](../../results/raw/redteam/synthetic-20261109-foundry/cases/ADV-V17/B/native/circomspect/circuit-00.stderr). Picus exit code 8 means properly constrained under Picus's own question, code 0 means inconclusive, and timed-out invocations remain TIMEOUT; the exact code meanings are in the pinned [Picus source](</Users/imranpollob/Coding/bc/bindcheck-zk/tools/picus-src/picus/exit.rkt>). On the synthetic set, Picus returned [exit 8 for all 46](metrics.json), yet that circuit property does not decide application authorization. In DEV, [26 Picus invocations returned 8](metrics.json), [4 returned 0](metrics.json), and [11 timed out](metrics.json). The [native status ledger](metrics.json) also preserves Slither, Foundry, Circom, Circomspect, Picus, and ZKAP availability per row; absent tools and failed builds are never scored as misses.

## What the comparison supports

**Beatable at E1 screening.** Arm C flagged [all 23/23 labeled vulnerable cases](metrics.json), including [11](case-comparison.csv) on which BindCheck remained UNKNOWN. The extra cases include guard, replay-position, array, mask, decoding, and nullifier-scope source shapes in the [case ledger](case-comparison.csv). Arm A alone flagged [17/23](metrics.json). These findings show how much value simple consumer/verifier checks and policy-aware joins can reproduce without solving the joint relation; they do not establish real-proof exploitability.

**Not matched in warning restraint.** Arm C warned on [13/23 legitimate cases](metrics.json), compared with BindCheck's [3/23](metrics.json). BindCheck left [20/23 legitimate cases UNKNOWN](metrics.json), so this is a warning-rate observation, not verified precision or safety. The mock-verifier Foundry harness yields E1 policy screening only. Circuit-only Picus safety results cannot clear a consumer binding obligation. No independent held-out or E4 advantage follows from these development fixtures.

**Assumptions and limitations.** The synthetic contracts and policies are AI-authored and require author review; several verifiers are simplified. The scoring above treats any BindCheck pattern violation as a possible detection, regardless of relevance, and gives A/C the same upper-bound treatment in the aggregate. Several baseline native runs exited nonzero or timed out, but their full records are retained rather than recoded as negative findings. The source-only arm C does not validate R1CS semantics or proof acceptance. The case count mismatch and unavailable ZKAP preclude a complete requested-size comparison.

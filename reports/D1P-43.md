## 2. Interface and rule

The documented interface is:

```python
role_result = analyze_role_binding(
    analysis,  # a successful static_analyzer_v1.analyze result
    producer_source=noir_main,
    producer_support_sources=[hashing_library],
)
```

Before inference, the module requires the current analysis schema, an
extracted relation, an unchanged relation hash, equal producer/relation word
widths, exact normalized boundary origins, successful consumer paths, and
exact scalar Noir source/artifact public-ABI order. A failed precondition
raises `RoleBindingUnsupported`; callers must report `UNKNOWN`, not silence.
The main analyzer therefore remains the controlling public-input-mapping and
dynamic-memory gate.

The returned `bindcheck.role-binding.v1` record contains one entry per verifier
word:

- producer ABI role and identity;
- producer commitment/hash inputs, computed outputs, tree-root/tree-member
  roles, domain inputs, equality branches and constraint guards;
- consumer boundary role and identity;
- successful-path guards and the committed effects those guards authorize;
- state identity and admission polarity; and
- direct amount/beneficiary effect operands.

`R-ROLE` distinguishes `boundary-role`, `domain-identity`,
`producer-state-membership`, `state-identity`, `polarity`,
`effect-authorization`, and `effect-beneficiary`. Unknown identifier roles do
not produce mismatch warnings.

### 4.1 What the join adds

The prior full rule `R-EFFECT` could join a missing producer occurrence to a
direct effect operand, but it could not distinguish the correct state set,
domain identity, word role, polarity, or effect authorization. `R-ROLE` adds a
typed relational join: it can say that both sides use a word yet use it as
different things. On this small exposed set that changes full versus union by
two supported detections (7/7 versus 5/7), rather than merely adding a more
detailed warning to an already detected case.

The stronger unique statement is therefore bounded: BindCheck can relate a
producer-enforced word role to the exact consumer state identity or committed
effect role it authorizes. It still cannot establish exploit reachability or
generalize from these development examples.

## 7. Limitations and provisional verdict

- This is development evidence over known mutants. It is not held out and the
  final experiment still requires a rerun after the extractor/tool freeze.
- Role names and application identity atoms are bounded source-derived facts,
  not compiler-semantic proof. Unknown roles produce no mismatch warning and
  silence is not safety evidence.
- The source/artifact interface currently requires scalar public ABI leaves and
  explicit support-function signatures. Source hashes and ABI order are
  checked, but the module does not replace ACIR semantic provenance.
- Consumer authorization is limited to the checked relation's successful
  guards, committed writes and modeled token effects. It does not prove a
  minimal causal authorization slice.
- Payy exact mapping and dynamic-memory fidelity remain unresolved. No stale
  D1P-34 selector-prefix fact is used.
- No solver, proof, replay, live chain, held-out project or security validation
  ran. All research verdicts remain `UNKNOWN`.

**Provisional verdict:** the typed join adds a real diagnostic capability over
the unjoined union: correct state/domain correspondence and effect
authorization, not unused-word discovery. The deeper relationship most likely
to increase what only BindCheck can say next is a compiler-backed,
transitive authorization graph from each producer computation (exact tree,
note and domain identity) through the verifier position to the minimal
consumer guard/state transition/effect it authorizes. That would replace name
heuristics and distinguish direct operands from policy-relevant authorization.

Recommended next task with a measurable completion criterion: resolve the
Payy 1005-to-1003 mapping and dynamic-memory address/path gates, freeze the
analyzer, relations, role module and all input hashes, then run the single
D1P-43 command exactly once. Completion requires all supported targets to have
predeclared warning associations, all unsupported targets to name their gate,
and zero post-output label changes.

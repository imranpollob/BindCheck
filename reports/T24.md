## 3. General repairs

### Include and build coverage

The Circom resolver recursively follows circuit-relative, dependency-relative,
repository `node_modules`, package/lockfile-declared, and common monorepo
layouts. If an authorized dependency is absent, it can use the locally
vendored `circomlib@2.0.5` only after verifying the pinned package/tree hashes
in `bindcheck_zk/vendor-lock.json`. The final run records 155 vendored-pinned
include resolutions across 27 rows, 378 dependency-relative and 154
circuit-relative resolutions; 62 include references remain unresolved across
14 rows. Every build records the include source.

Inventory now prioritizes `.circom`, `.nr`, `.sol`, manifests and lockfiles,
and excludes `.git`, dependency, frontend, build, distribution, vendor, and
test-fixture trees before applying the 2,500-file cap. All 56 rows record their
excluded paths (164 exclusion records total). The only capped row is DEV-F30;
its relevant ZKredential circuits/contracts survive the cap.

Generated-verifier recovery is allowlisted and repository-directed: it is
eligible only when the repository's own scripts describe a complete fresh
local setup/export pipeline and a compiled R1CS exists. No arbitrary repository
script is executed. In this run three rows lacked a recipe and one had a recipe
but no compiled R1CS, so all four remain `UNKNOWN`; no generated verifier was
fabricated.

### Discovery and decision quality

The repairs add entry-circuit filtering, main-template Circom scoping,
verify-only consumer retention, verifier-wrapper exclusion, receiver-type and
token matching, uncapped internal candidate scores, exact dynamic allocation
lengths, nested mapping parsing, helper-aware replay analysis, and bounded
replay-key-to-verifier dataflow. P5 now emits a mismatch only for complete or
compiled interfaces and treats lexical semantic disagreement as `UNKNOWN`.
P4 recognizes reject-style and alias-based field guards, delegated helpers,
fail-closed placeholders, and unsupported Honk/custom/STARK layouts without
mislabeling them as Groth16 guard failures.

Temporary R1CS/SYM build directories are removed at the end of each analysis.
During development, 103 analyzer-owned scratch directories (2.58 GiB) from
earlier attempts were identified by their exact `bindcheck-zk-r1cs-*` prefix
and removed; raw evidence and repository data were untouched. The final runs
left no such directory behind.

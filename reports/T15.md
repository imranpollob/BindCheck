## 1. The property, from source

**Protocol intent (documentation and comments).** `agg_utxo` writes the exported words of its leaf proofs from index 0, mint = 4 words and burn = 5, and forces every other output word to zero (`noir/agg_utxo/src/main.nr` l.149–154, both revisions). `agg_agg` comments say exportable kinds "consume the next x messages" and that padding proofs "cannot have messages"; the Rust mirror `AggAgg::messages()` (`pkg/zk-primitives/src/agg_agg.rs`) is "compacted with trailing zeros".

**Active vs padding, as `agg_agg` computes it** (`noir/agg_agg/src/main.nr` l.27–79 at B; same logic at A): for each inner proof, a walker (`next_check`) steps over kind 2 (4 words) and kinds 3/4 (5 words); the first word that is not at a record start with such a kind ends that proof's region (`has_ended`), after which its words must be 0 ("messages cannot have gaps"). Every word before the end must equal the outer public `messages[messages_index]`, and `messages_index` counts these words across both inner proofs. **Active region = outer indices `< messages_index`; padding = indices `>= messages_index`.** A padding proof (`old_root == 0`) contributes none. No count is fixed by us; for the test input it is 4 (one mint), the same value the upstream Rust `AggAgg::messages_count()` gives.

**What each revision mechanically enforces on the outer `messages`**

| | A `c4d2c90` | B `dcd5d96` |
|---|---|---|
| Words `< messages_index` equal the inner proofs' exported words | yes (l.74) | yes (l.75) |
| Words `>= messages_index` constrained | **no assertion reads them** (source reading; tested below) | `assert_message_tail_zero(messages, messages_index)` called once at l.108 after both proofs: for `i >= messages_index`, `assert(messages[i] == 0, "Message is not zero")` (l.117–123); two Noir unit tests (l.125–146) |

`agg_final` only copies the 1000 words into `agg_agg`'s public inputs (`messages` at l.14, copied at l.27–29), and the message-tail check in `agg_utxo` bounds the leaf output, not `agg_agg`'s outer words. The consumer source (`eth/contracts/rollup3/RollupV1.sol`) is byte-identical at A and B. Its parser `verifyAllMessages(3, …, messages_length)` walks **every** slot (kind 0 → skip one, 2 → `verifyMint`, 3 → `verifyBurn`, otherwise revert). So a kind-3 record in a padding slot would be read as a burn by that parser; this is a source reading, **not executed here**, and what `verifyBurn` does with it (`executeBurn`) is not examined.

## 2. Witness design

Both cases use the same inner proofs per revision (T13's route: one mint utxo, `agg_utxo` with two default padding bundles, `agg_agg` with the real `agg_utxo` plus a padding proof), regenerated separately at each revision.
- **Control:** the upstream conversion's input: outer `messages` = the 4 mint words `[2, note_kind, 100, mint_hash]`, then zeros.
- **Candidate:** identical, except outer indices 4–8 are a syntactically valid five-word burn record `[3, note_kind, 7, 424242, 0xdead]` (kind 3, note kind of the active mint, synthetic value, hash and address). Index 4 is the first padding slot by the rule above. The active sequence (indices 0–3) is unchanged. The record is synthetic: no burn utxo, note or proof stands behind it.
Harness: `payy-harness/t15_tail.rs`, one new untracked file per checkout; no circuit, key or constraint is touched. `Prove::prove` runs the revision's own compiled `agg_agg` in the ACVM first (failure is returned before any `bb` call), then `bb prove`.

The controls pass in both, consistent with the documented semantics being intended to match for the valid sequence.

## 4. What the evidence supports, and what it does not

**Supports (one candidate, one position).** (a) A's `agg_agg` circuit places no constraint on an outer message slot at index `>= messages_index`; one concrete nonzero record at index 4 was proved and natively verified. (b) B's helper rejects that same witness, and the assertion cited is the helper's (l.120, called from l.108), not another check. (c) The control is unaffected by the change. (d) The two circuits' only functional difference in the `agg_agg`/`agg_final` path is this check (formatting aside; `noir/agg_agg` diff in `11_agg_agg_diff.txt`; `agg_final` differs only by the new `agg_agg` key-hash constant).

**Does not establish.**
- Only index 4 and a burn-shaped record were tried. Gaps before the record, mint-shaped records, tail positions near 1000, several records, a nonzero active prefix with different counts, and padding-proof combinations are **not run**.
- The old-revision candidate proof was not passed to `agg_final`, the Solidity verifier, or the consumer; whether a block built on it would be accepted, which validators sign what, who may submit it, and what `verifyBurn`/`executeBurn` would do are **not run** and not examined. No cross-key rejection was tested (A's proof was not tried under B's key, B was not given A's artifacts).
- Whether revision A's circuits were ever deployed anywhere is outside this evidence. Proof acceptance alone is not loss; no vulnerable/fixed classification is made. The result concerns the circuits, with the consumer reading above only a source observation.
- The advisory itself is not reproduced; this experiment cannot tell whether the advisory's scenario matches this candidate.

**Local deviations (all recorded).** Revision A's committed `Cargo.lock` is rejected by `--locked` (432 unused entries, missing local package `rustbridge`); cargo rewrote it once and `22_lock_check.txt` shows no third-party version changed. It is the only upstream file modified (A's worktree `tools/cases/payy-c4d2c90`; B's checkout has only the untracked `tests/` files). `ProofInputs` is private at A, so the harness uses only `Prove::prove` and `Error` variants, identical at both. The first test run overflowed the default test-thread stack (the generated input struct is large) before any proof work; `RUST_MIN_STACK=512 MiB` is set by the script. See `results/raw/T15/attempts/`. T01–T14 files are unchanged (T10 and T13 proof hashes re-checked).

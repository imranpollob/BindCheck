# T09 — Can one existing Payy proof fixture be verified reproducibly?

**This task does not reproduce the advisory or establish acceptance of an unauthorized message tail.**

Authorized defensive research using public artifacts and local tools only. No deployed contract or public network was used for verification (the only network access was fetching sources, two toolchain tarballs and the public CRS file). T01–T08 files are unchanged (only `.gitignore` gained ignore lines).

## 1. Result

**BLOCKED at the proof/public-inputs link; the Noir-side chain is otherwise reproduced.**

At both pinned revisions, *source → circuit artifact → verification key → Solidity verifier* reproduces exactly for `agg_final`. The committed `fixtures/proofs/agg_agg_final_evm_proof.proof` is **not** a proof for that key: it is a serialized Halo2-era `EvmProof::V1` wrapper written by a Rust harness that no longer exists at the pinned revisions, and the repository ships no public-inputs file for `agg_final`. Native verification could not be performed, so no Foundry test against the real verifier and no altered-input control were run (preconditions not met; both are **not run**).

Reproduce: `bash scripts/t09.sh` (21 steps; measured 8 s on a rerun with toolchains and the CRS already cached; exit 0 means every step behaved as recorded, not that a proof verified). Logs: `results/raw/T09/`; summary: `results/raw/T09/90_summary.json`.

## 4. Native verification of the existing fixture

Commands (full lines in the logs; `bb` = the pinned binary):

| Step | Command (abridged) | Exit | Observed |
|---|---|---|---|
| Repo flavor, as the generator implies | `bb verify --scheme ultra_honk --oracle_hash keccak -k <key> -p agg_agg_final_evm_proof.proof` (A and B) | 1 | `Unable to open file: ./target/public_inputs`. No public-inputs artifact exists to pass. |
| **Diagnostic only** (not a verification): zero-filled placeholder public inputs, 1019 × 32 bytes, with `keccak`, `keccak --disable_zk`, `poseidon2` (A and B) | `bb verify … -i diag_zero_public_inputs_1019x32` | 1 (all six) | keccak and keccak+`--disable_zk`: `Assertion failed: (val.on_curve())`; poseidon2: `Conversion error here usually implies some bad proof serde or parsing`. `bb` fails while deserializing the proof, before any verification equation, so the failure is about the file's format and not about the placeholder inputs. |

**Why the file is not an UltraHonk proof (mechanical, `30_proof_decoded.json`):** the 4365 bytes parse with every byte consumed as Borsh `EvmProof::V1` = tag `0`, a 3328-byte proof, 12 aggregate instances, two roots, 18 UTXO inputs (`1+4+3328+4+12·32+32+32+4+18·32 = 4365`). That is the older Halo2 consumer's argument shape. A Honk proof is a whole number of 32-byte fields; 4365 mod 32 = 13.

## 5. What the fixture contains (and under which layout)

Decoded with the **Halo2-era** layout, not the pinned Noir/`rollup3` layout, and with big-endian words as the older consumer reads `bytes32` (endianness of the Rust serialization is **U**): all six `(root, mint/burn hash, value)` slots have mint/burn hash `0` and value `0`, and the same root `0x100c5ec5…` repeated. Under that layout the fixture carries **no application messages** (an empty/padding block). The Noir message grammar (`[oldRoot, newRoot, commitHash, messages…]`, kinds 0/2/3) does not apply to this file, so nothing can be said about Noir messages from it.

Three claims kept distinct: native proof verification — **not achieved**; Solidity verifier acceptance — **not run**; full consumer settlement — out of scope.

## 6. Limitations and caveats

- The Noir-side reproducibility concerns `agg_final` only; `agg_agg`/`agg_utxo` keys and the recursive inner proofs were not examined.
- `bb` is a Payy-built binary (see §2). `nargo` cached dependencies in `~/nargo`.
- Placeholder-input diagnostics prove nothing about validity; they only classify the failure stage.
- I did not try to build the Halo2-era tag, which would need the old Rust stack and 258 MB of KZG parameters and would exercise a **different consumer** from the one selected in T08.
- The advisory's version labels remain inconsistent with the Noir sources (T08 §3); this task does not resolve that.
- Full commit IDs and artifact hashes are in `results/raw/T09/10_artifacts.tsv`; step statuses in `steps.tsv`.

## 3. Manifest and seal behavior

`prepare-run` records:

- Git commit, branch, dirty flag, and porcelain status;
- platform, Python and Git executable paths, byte hashes, and versions;
- caller-supplied tool identities and versions;
- configuration and input paths, sizes, and SHA-256 values;
- declared seeds; and
- wall-time, memory, and call budgets. An unspecified budget is explicit
  `null`, not implicit authorization for unbounded work.

`seal` refuses to overwrite an existing manifest, hashes regular files in
stable path order, excludes its own output and the named mutable indexes
`.DS_Store`, `latest.json`, and `run-index.json`, and records exclusions. The
authoritative future evaluation manifest must be retained by the custodian
outside the developer workspace. A local seal detects changes relative to
that retained copy; it is not access control, authorship proof, or secrecy.

`verify` checks every member's size and SHA-256 and returns exit 2 on a
mismatch. `self-test` exercises preparation, sealing, positive verification,
and negative tamper detection only on a fresh disposable directory.

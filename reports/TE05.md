# TE05 — PY-C02's own contribution: active-prefix candidate end to end

Date: 2026-10-30 (lane-x-muse). Status: DONE (PY-C02 W001 E3 on its own
mutation; W002 E1-contained; TE04 relabeled to the inherited tail defect).

## Objective

Per the author policy review
(`docs/validation/policy-review-2026-10-30.md`), TE04 wrapped the TAIL
candidate (messages 4–8), which the original `c4d2c90` circuit also accepts
(TC02), so TE04 is E4 for the inherited Payy message-tail defect, not for
PY-C02. This task runs the ACTIVE-PREFIX candidate (attacker mint record at
messages 0–3, no inner proof behind it) through the mutant stack with its
own matching proof and key, on the same consumer and initial state as TE04,
and checks the original/repaired circuits with the same witness.

## Commands and observed results

All local, serial, `nice -n 19` for proving; disk stayed above 19 GB free.

1. `bash scripts/te05_part1.sh` (slot `009`): `nargo compile --package
   agg_final` exit 0; `nargo execute` exit 0; `bb write_vk --scheme
   ultra_honk --oracle_hash keccak` exit 0; `bb prove -k <own key>` exit 0
   (proof 10,560 B); `bb verify` exit 0 ("mutant agg_final ACTIVE proof
   verifies"). The derived final VK is byte-identical to TE04's
   (`cmp` clean; hash `0x4ca9f3ce…3a52ccbf`), so TE04's deployed
   `HonkVerifierMutant` applies unchanged.
2. Active-slot check: `009` public inputs carry the attacker mint
   `[2, note_kind, 100, 0x…abababab]` at messages 0–3 and zeros after;
   `007` (TE04) carries the honest mint at 0–3 and the forged burn at 4–8.
3. `python3 scripts/te05_part2.py` (anvil port 18559, fresh chain):
   deploys usdc/vMut/vPin/impl/proxy ok; control mint `0x1e05…4d103`
   (100) registered; pinned verifier added. `pinned_contrast` at height 1:
   REVERT. `mutant_block` at height 1: REVERT. Both revert with
   `RollupV1: Mint value invalid`. Final state: `blockHeight` 0, rollup
   balance unchanged (100), attacker mint unspent.
4. Gate order (pinned `RollupV1.sol:314-371`): `verifyAllMessages` (message
   policy, incl. mint registration) runs BEFORE `verifier.verify(proof)`.
   Both submits reverted at the message gate, so neither proof reached
   onchain verification. The pinned "contrast" here is uninformative about
   keys and is NOT claimed as one. Proof acceptance for the active block
   rests on native `bb verify` under the mutant final key (step 1) plus
   TC02's native verify of the inner active proof under the mutant
   `agg_agg` key.
5. Original/repaired: the mutant `agg_agg` differs from pinned `c4d2c90`
   by exactly line 74 (`diff` clean: the `:74` export assert replaced by
   the XBM comment; pinned sha
   `c44a67e6…8604d`). Restoring that line reproduces pinned bytes, so the
   repaired circuit IS the original. TC02's pinned run rejects the same
   active witness at ACVM witness generation (`Assertion failed: proof
   message must be exported`, 0.0 s, no `bb` call) — covering original and
   repaired with one observation.

## Grading (same-transaction, matching-keys rule)

- PY-C02 W001 (R-BIND): E3 on its own mutation — real mutant-keyed proofs
  at both aggregation levels accept attacker-controlled messages with no
  inner proof behind them; original and repaired circuits admit no proof
  for the same witness. Onchain, the block is contained at consumer
  message policy before proof verification.
- PY-C02 W002 (R-EFFECT `:850`): E1 — same-transaction runs under both
  keys revert at `Mint value invalid` with zero state change; no
  unauthorized committed effect was produced with an active-prefix proof.
  (The v1.1 table's E4 for this warning rode on TE04's tail block and is
  corrected by the ledger.)
- TE04: E4 for the inherited Payy message-tail defect (real historical
  bug: original circuit accepts the tail, mutant-keyed proof verifies
  onchain, pinned consumer settles the forged burn 100→93 / 0→7). NOT
  evidence for PY-C02's own mutation.

## Assumptions and limitations

- Honest control: the registered control mint (100, unspent) succeeds;
  the chain prefix (validator key, note kind, funding) is synthetic
  (anvil + synthetic validator key). No live network or real keys.
- The active-prefix ceiling on the pinned consumer is containment: an
  unregistered forged mint cannot settle, with or without PY-C02. A
  combined circuit+consumer gap (e.g. PY-C02 with PY-S01's removed
  admission) is out of scope for single-mutant grading.
- No cargo rebuild was needed: TC02's preserved `009` artifacts, TE04's
  verifiers/artifacts, and pinned-source reads only.

## Failed approaches

- First replay run failed: `watch` set to the 32-byte attacker hash hit
  `balanceOf` address validation — fixed by `te05_replay.ts` (state via
  `getMint`).
- First harness launch failed: `tsx` unresolvable because
  `node_modules` symlinked to the unset-default backend path — fixed by
  exporting `BINDCHECK_WARPTOAD_NODE_MODULES` (sibling reference tree),
  `BINDCHECK_PAYY_REF`, and `BINDCHECK_SOLC_0_8_20` before running.

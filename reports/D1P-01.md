## B. Provenance-checked intake

[`d1p_01_n8_intake.py`](../scripts/d1p_01_n8_intake.py) reads expected
identities from
[`d1-01-execution-manifest.json`](../metadata/d1/d1-01-execution-manifest.json)
(SHA-256
`00b965f2d918506f5c8660ad5468303e82fb671291432a6aaeb9821a4ac57033`).
It resolves the historical absolute Linux paths by unique role-specific
suffix, while every actual manifest, code, specification, input, and output
path is supplied or resolved locally. It does not embed a historical checkout
root.

Validation precedes module loading, ACIR parsing, output-directory creation,
and query generation. With matching files, it additionally checks the N=8,
two-stream walk schema, parses both ACIR/ABI pairs, and requires eight message
expressions and two eight-word activated streams per pair.

The query path uses the unchanged `t22_v5_compact.run_one` builder, but
temporarily replaces both boundaries that could reach a solver:

1. `FF.solve` writes the exact v5 header, accumulated assertions,
   `(check-sat)`, and `(get-value ...)` bytes using exclusive creation, then
   raises `SerializationComplete` instead of returning a status;
2. `_run_killable` is replaced independently by a fail-closed function that
   raises `NO_SOLVER_BOUNDARY_VIOLATION` if reached.

The originals are restored in `finally`. No `solver.json`, SAT/UNSAT value,
simulated timing, or simulated solver record is created. A fresh intake
manifest is written only after complete file validation and query generation.
It records `solver_processes_launched: 0` and compares each serialized file's
actual SHA-256 with its frozen manifest value.

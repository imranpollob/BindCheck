## 1. Outcome

BindCheck v1.1 removes the Solidity source-name/regex profile from the
analysis path. A consumer is now accepted only through a source-hash-checked
compiler-AST relation. The new frontend recognizes the verifier boundary from
the declared interface type—a call with proof bytes and a public `bytes32[]`
whose declaration returns `bool` or is reverting—then follows public words
through internal calls, guards, storage writes, and shared signature-based
effects. Missing compiler-AST facts fail closed as
`UNSUPPORTED_CONSUMER_AST_REQUIRED`.

The unchanged 30-mutant development evaluation improves from **13 detected / 16
unsupported / 1 miss** in D1P-31 to **16 detected / 14 unsupported / 0
misses**. All 16 detected targets point to the named semantic boundary; this
is 16/30 over all targets, not a supported-only capability estimate. The
newly covered cases are WT-S06 and Payy PY-S01/PY-S02. Fourteen target-alone
semantic obligations remain unsupported.

The 30 analyses emit 53 warning objects: 20 match the named mutations and 33
are unrelated inherited warnings. None is adjudicated a confirmed semantic
false warning. “Unrelated” does not mean false: the Payy baseline intentionally
retains the producer message-tail defect, and its consumer leaves the
commitment word without a guard, state write, or modeled effect.

All 53 mutant warnings were passed through the unchanged D1P-31 validation
index. WT-C03 retains its correspondence-checked preserved E4 route with two
manual steps; 52 warnings remain E1 for lack of a content-addressed route.
No proof generation, solver, fork, or live-chain action ran.

## 2. Application-neutral consumer lowering

The analysis path contains no contract, application, verifier-function,
guard-function, or storage-field spelling. A focused regression scans the
analyzer and frontend for the removed identifiers and passes.

The lowering is structural:

1. solc declaration IDs and type descriptions identify exactly one verifier
   call with proof bytes plus a public-input array;
2. the array is propagated through internal calls using declaration IDs;
3. every word is classified as calldata, environment, or consumer-supplied
   state/configuration;
4. conditions become guard dependencies, and declaration-ID storage paths
   plus public-derived keys become state identities;
5. assignments to state become committed storage effects;
6. standard token calls are recognized only through the shared function-type
   table in `protocols/d1/bindcheck-v1.1-effect-models.json`;
7. a boolean-true write is paired with a prior boolean-false condition only
   when the structural storage declaration path and derived key agree; and
8. the rich D1P-18/21B relation route is normalized with the same symbol,
   storage-select, effect, and replay identities. The verifier relation itself
   is not counted as an independent consumer use.

R-CONSUMER is the new generic diagnostic: a calldata-derived verifier word
must reach a guard, committed state, or modeled effect. It replaces the old
name-driven missing-anchor cases without guessing a root/nullifier role. A
consumer-supplied configuration word is not required to have a second use
outside the verifier boundary.

The full Payy AST demonstrates generic burn coverage: the shared table
recovers `token-transfer` and `token-transfer-from` calls, including the
low-level burn encoding, along with storage writes. It also structurally
pairs the absent-record guard with the later same-record boolean write. The
loop index is intentionally widened to the 1,000-word record tail; this is a
conservative dependency slice, not exact Solidity path equivalence.

Payy has 1,005 producer ABI leaves but a 1,003-word direct verifier array. The
frontend derives the two-word recursive-verifier-selector prefix from the
largest public ABI array and the AST's three-word direct-array header. That
checked mapping correctly places old state, new state, commitment, and the
1,000 message words at producer indices 2, 3, 4, and 5–1004. The prefix-width
derivation is recorded as a limitation; it is not silently assumed.

## 3. Corrected producer use accounting

v1.1 separates three occurrence roles:

| role | counted behavior |
|---|---|
| proof-enforced use | arithmetic assertions; black-box inputs **and outputs**; memory-operation address/value expressions; constrained calls |
| witness generation | Brillig inputs, outputs, and predicates, inventoried separately and never sufficient for R-BIND |
| definition only | `MemoryInit` cells, recorded separately; initialization alone does not discharge a use without a memory operation |

This fixes the v1 undercount of integer-encoded black-box outputs, beta.14 and
beta.22 Brillig outputs, and memory-operation expressions while preserving the
D1P-30 rule that Brillig is witness-generation machinery. The full earlier
Payy artifact therefore has 999 producer leaves with no proof-enforced use
(`messages[1]` through `messages[999]`); each is separately present once as a
memory definition. The full check-added artifact has zero unused public
leaves.

## 7. Limits

- Both applications and all 30 mutants are exposed development data; no
  held-out project or family was inspected.
- The AST frontend is not Solidity semantic equivalence. It widens dynamic
  loops and supports a bounded statement/expression subset.
- The two-field Payy selector prefix is a checked ABI/header-width inference,
  not a proof of the recursive verifier's cryptographic semantics.
- Occurrence proves syntactic proof-enforced use, not injectivity, intended
  hash construction, policy, or dependency strength.
- R-CONSUMER detects absence of any modeled downstream use; it does not infer
  which protocol-specific guard/effect was intended.
- The evaluation has 33 unrelated warnings because the Payy mutant baseline
  inherits two development defects. Warning-object precision should not be
  reported without that qualification.
- Only one warning has a preserved E4 route under the unchanged validation
  index; automatic witness synthesis remains absent.
- No baseline arm, held-out transfer, solver campaign, new proof, live-chain
  action, prevalence estimate, capability result, security verdict, or D1
  verdict follows. D1 remains **UNKNOWN**.

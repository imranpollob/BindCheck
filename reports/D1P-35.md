## 1. Outcome

BindCheck v1.2 adds exact compiler-identity dispatch for Noir
`1.0.0-beta.15` through `1.0.0-beta.21` and corrects consumer warning source
locations. The change is deliberately limited to ACIR container decoding and
reporting:

- beta.15–18 use the already checked beta.14 bincode reader;
- beta.19–21 use MessagePack compact format 3 with the additional
  `current_witness_index` circuit field, while opcode and ABI interpretation
  continues to delegate to the fail-closed beta.22 implementation;
- beta.3 was compiled and inspected, but its distinct legacy schema was not a
  cheap safe extension and remains unsupported; and
- missing verifier-call lines are recovered only when the recorded interface
  call has one unique source occurrence. Ambiguity remains `:?`.

The unchanged D1P-34 evaluation records **16 detected / 14 unsupported / 0
misses**. All warning identities, reasons, evidence and non-location facts are
identical. Exactly 20 warning locations change, all six emitted unknown-line
warnings become concrete, and Payy R-EFFECT points to the payout effect rather
than an unrelated earlier write. No rule, threshold, R-* condition, shared
effect-table entry, or definition of a proof-enforced use changed.

## 2. Development-only version validation

The same small circuit was compiled independently with official arm64 Darwin
`nargo` releases for beta.14 through beta.22:

```noir
fn main(left: pub Field, right: pub Field, secret: Field) {
    assert(left + secret == right);
}
```

The fixture contains one `AssertZero`. In every beta.14–22 build the decoder
recovers the same public leaves and occurrences: `left` at witness/public index
0 with one occurrence and `right` at witness/public index 1 with one
occurrence. No held-out artifact was used to build or test the adapter.

| versions | encoded form observed | validation result |
|---|---|---|
| beta.14 | legacy bincode | reference passes |
| beta.15–18 | byte-identical decoded bincode to beta.14 | pass via unchanged beta.14 reader |
| beta.19–21 | compact MessagePack v3, seven-field circuit including `current_witness_index` | pass through the version adapter |
| beta.22 | compact MessagePack v3, six-field circuit | reference passes via unchanged beta.22 reader |
| beta.3 | distinct legacy schema | compiled and hash-recorded; unsupported |

The exact compiler identities, release URLs, archive and binary checksums,
compile commands, artifact hashes, decompressed hashes and decoded inventories
are in
[`version-validation.json`](../results/raw/D1P-35/version-validation.json)
(SHA-256 `82cb23076cbee496f015bfbe24b82c404ee74e51e666c15625fb0ea0bf75c187`).
All ten compiles returned zero.

This validation establishes the observed container layouts and the tested
one-opcode/public-leaf behavior. It is not a claim that every opcode encoding
used by every beta.15–21 program is supported. D1P-36 later confirms this
limit: two beta.21 programs reach a named fail-closed
`BETA22_MEMORY_OPERATION_ENCODING` condition for a MemoryOp payload absent
from this development fixture.

## 3. Location reporting

Two reporting-only helpers were added:

1. `_reported_boundary_location` uses the already recorded verifier declaration
   or expression name and reports a line only when the source contains one
   matching member call. It neither creates nor changes a consumer dependency.
2. `_effect_warning_location` selects among effects already recovered by the
   unchanged frontend and already carrying a vulnerable word. An existing
   external effect is preferred over a bookkeeping storage write. It does not
   recognize a new effect or change the vulnerable indices.

Consequently, WarpToad warnings previously printed as
`WarpToadCore.sol:?` now point to the unique verifier call at line 161 (or the
corresponding shifted mutant line). Payy R-EFFECT now points to
`RollupV1.sol:522` in the base source, with the expected line shifts in three
mutants. WT-C08 similarly reports the recipient mint rather than the preceding
fee mint because its vulnerable word reaches the former.

The comparison ledger records six unknown emitted warning locations before
the change and zero after it. D1P-34 raw consumer summaries contained 20
additional `:?` boundary strings that were not warning objects; the rerun also
resolves those without changing analysis outcomes.

## 4. Rule-preservation gates

The freeze compares the base and v1.2 trees in two ways:

- the shared effect table, beta.14 reader, beta.22 reader and Solidity AST
  frontend are byte-identical; and
- normalized AST hashes are identical for `_expression_witnesses`,
  `_nested_witnesses`, `_opcode_witnesses`, `_leaf_bindings`, `_ranges`, and
  for the rule-bearing portions of `analyze` and `load_relation_consumer` after
  removing only reporting-location expressions.

Focused tests cover all nine beta.14–22 fixture decodes, beta.3 rejection,
unique-line recovery, ambiguous-line retention, and payout-location selection.
The v1/v1.2 unit set passes **16/16** and the unchanged beta.22 decoder set
passes **8/8**. Python bytecode compilation also passes. `pytest` is not
installed in this environment; these suites ran directly with `unittest`.

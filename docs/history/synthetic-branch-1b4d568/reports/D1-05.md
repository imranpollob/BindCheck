# D1-05: Consumer-Directed Refinement

**Status:** DONE  
**Date:** 2026-10-23  
**Protocol:** `protocols/d1/d1-05-refinement.md` v1  
**Prerequisite:** D1-04 (fair baselines)

## Objective

Add consumer-directed abstraction-refinement (CEGAR) to the joint-semantics
pipeline. Demonstrate at least one spurious abstract candidate being rejected
by concretization and refined without removing a real violation. Preserve
clean controls and show what mechanism differs from D1-04.

## Mechanism

The CEGAR loop for `auth_unmatched`:

1. **Abstract model**: start with 0 ACIR producer constraints. The consumer walk
   structure (slot iteration, kind matching, burn/mint identification) is included;
   the producer's internal constraints on witness values are omitted.
2. **Abstract solve**: run `auth_unmatched` against this loose model.
3. **Concretize**: fix the candidate's message/permission values, encode ALL ACIR
   constraints, check SAT. If the full producer is consistent with the candidate,
   it is a real violation.
4. **If spurious** (concretization UNSAT): add ACIR constraints relevant to the
   candidate's witnesses (direct + one transitive hop). Repeat from step 2.

This is standard CEGAR adapted for the joint producer/consumer domain: the
abstraction is consumer-directed (uses consumer structure, omits producer
internals), and the refinement is witness-directed (adds constraints that
mention the failing candidate's witnesses).

- **CEGAR time:** 11.75 s (2 iterations)

The abstract model (0 constraints) found an unauthorized burn candidate, but

## Completion criteria assessment

1. **Spurious candidate rejected:** Yes — both cases had a spurious abstract
   candidate at iteration 0, rejected by concretization (UNSAT against full
   ACIR constraints). This is the required demonstration.

2. **Real violation preserved:** Yes — synth-faulty still yields VIOLATION with
   a replayed concrete model, confirmed through concretization.

3. **Clean controls preserved:** Yes — synth-repaired yields VERIFIED_WITHIN_SCOPE
   with replayed non-vacuity. Coverage (COV) UNSAT for both cases.

4. **Mechanism differs from D1-04:** The CEGAR loop adds a concretization check
   (absent in B1–B3) and automatic constraint selection (absent in B3's manual
   summary). B2 encodes all constraints monolithically; D1-05 starts with 0
   and adds selectively. B1 tests specific inputs; D1-05 explores the full
   constraint space.

## Honest assessment

**The CEGAR mechanism works correctly but provides no measurable advantage on
these small synthetic circuits.**

- **Refinement is coarse-grained:** The one-hop transitive closure from the
  model's 18 witnesses (9 msg + 9 perm) reaches all 26/35 ACIR constraints
  in a single refinement step. On these small circuits, every constraint
  mentions at least one public witness within one hop. Selective refinement
  would require either larger circuits (where only a subset of constraints
  is reachable) or a slot-targeted refinement strategy.

- **CEGAR is slightly slower than monolithic:** synth-faulty 11.75 s vs 11.4 s
  (3% overhead); synth-repaired 107.3 s vs 98.0 s (9% overhead). The overhead
  comes from the concretization solver call. This is expected — CEGAR adds
  solver calls; its speed advantage comes from smaller individual queries, which
  requires constraints that can be omitted.

- **The concretization check is the genuine new mechanism.** It provides a
  soundness guarantee that B3's manual summary lacks: a candidate is only
  reported as a VIOLATION after the full producer confirms it. This would have
  caught B3-style over-approximation errors.

- **No consumer-directed *selection* advantage yet.** The mechanism selects
  constraints automatically (better than B3's manual effort), but doesn't select
  *fewer* constraints than B2 on these circuits. The hypothesized advantage
  requires circuits where the producer has many constraints irrelevant to the
  consumer's authorization goals.

## Assumptions and limitations

- **Synthetic cases only.** N=9, 3-word stride, 0 RANGE opcodes.
- **Coarse refinement.** All constraints added in one step; selective advantage
  untested.
- **Auth only.** CEGAR applied to `auth_unmatched` only; cov/nonvac use full
  encoder.
- **No consumer contract exercised.** Same limitation as D1-03.
- **CEGAR overhead.** Multiple solver calls add 3–9% time vs monolithic.

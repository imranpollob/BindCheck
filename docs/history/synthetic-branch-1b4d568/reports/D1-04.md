## Baseline descriptions

### B1: Direct Foundry tests (7 tests, all pass)

A `SynthSettlement.sol` consumer models the same N=9/3-word grammar and a test suite
supplies concrete valid-proof seeds matching the D1-03 solver models. Tests demonstrate
the VIOLATION (unauthorized burn in tail) and confirm the repair (no violations with
legitimate inputs).

**Strengths:** Orders of magnitude faster (<1 ms total). Tests the actual consumer code
path. Found the same VIOLATION. Easy to write and maintain.

**Weaknesses:** Tests specific inputs, not the full constraint space. Cannot prove UNSAT
(the repair blocks *all* unauthorized burns). Must be manually updated when the circuit
or consumer changes. Does not produce a formal guarantee.

### B2: Monolithic joint solving (no propagation)

Same joint encoder as D1-03 but skips the propagation pass (all 26/35 constraints
encoded directly as residual). Same solver, timeout, and goals.

**Result:** Identical verdicts and nearly identical times (within noise). Propagation
provides no benefit for these circuits because no witness values are fixed — propagation
has nothing to substitute. All 26/35 constraints remain residual in both cases.

**Implication:** The propagation pass is designed for circuits with fixed public inputs
(e.g., known VK hashes or state roots). For fully symbolic analysis with no fixed
values, it adds overhead without reduction.

### B3: Summary-based modular check (CIVER-style adaptation)

A manually written producer summary encodes: "if the authorized stream has ended (kind=0),
then authorized words are zero; if not ended, messages equal authorized; if ended AND
repaired, messages are zero." This is ~25 lines of specification logic, composed with
the same policy walk and goals.

**Result on faulty:** SAT in 1.0 s (11x faster than D1-03). The summary has fewer
constraints than the full ACIR, so the solver works faster.

**Result on repaired:** UNKNOWN (60 s timeout). The ite-based conditional encoding
interacts poorly with the finite-field solver on UNSAT proofs. The D1-03 pipeline
(encoding the actual ACIR multiplication-based conditionals) produces UNSAT in 98 s.

**Implication:** Manual summaries are faster when the goal is SAT (fewer constraints
to satisfy), but may be harder for the solver when the goal is UNSAT (the summary
encoding may not align with the solver's proof strategy). The manual summary also
requires analyst effort and must be updated when the circuit changes.

## Assessment

**Does the D1-03 pipeline add value over each baseline at this stage?**

1. **Over B1 (Foundry):** The pipeline produces a formal UNSAT/VERIFIED result that
   Foundry cannot (Foundry tests specific inputs, not the constraint space). However,
   Foundry found the same VIOLATION faster and with less infrastructure. For bug finding,
   Foundry with good seeds is a strong baseline. The pipeline's advantage is on the
   verification side (UNSAT proofs + non-vacuity).

2. **Over B2 (no propagation):** No measurable advantage on these synthetic cases.
   Propagation is expected to matter on real circuits with known public inputs (VK
   hashes, state roots, batch sizes). This needs to be tested on the actual Payy cases.

3. **Over B3 (manual summary):** The pipeline avoids analyst annotation (0 LOC vs ~25)
   and produces correct verdicts for both cases. The manual summary times out on the
   repaired UNSAT proof. The pipeline's automatic extraction from ACIR is an advantage
   for correctness and maintainability, though not yet for speed.

**Honest conclusion:** The D1-03 pipeline does not yet demonstrate a clear advantage
over Foundry testing for bug finding on these synthetic cases. Its value proposition is:
(a) formal UNSAT/VERIFIED results that Foundry cannot provide, and (b) automatic
extraction that avoids manual summary errors. These advantages need to be tested on
real circuits (D1-05/D1-06) where the constraint space is larger and manual summaries
are impractical.

## Assumptions and limitations

- **Synthetic cases only.** The comparison does not include real Payy circuits.
- **B3 UNKNOWN.** The manual summary times out on repaired UNSAT. A different encoding
  (e.g., using multiplication instead of ite) might resolve this, but that would be
  additional analyst effort.
- **B1 coverage.** Foundry tests check specific seeds, not the full constraint space.
  The test suite may miss violations that require different witness values.
- **No consumer-directed refinement.** D1-04 compares baseline methods; D1-05 adds the
  refinement mechanism that is the hypothesized contribution.
